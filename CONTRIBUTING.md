# Contributing

Thank you for taking the time to improve a project.

## Before you start

Read the repository's README, licence and any local contributor instructions. Public visibility alone does not grant permission to reuse source code. Project-specific guidance takes precedence over these defaults.

For a substantial change, open an issue first so the scope and approach can be discussed. Keep bug reports reproducible and focused on one problem.

## Proposing a change

1. Describe the user problem and the intended result.
2. Keep the change focused and follow existing conventions.
3. Run the checks documented by the project; report what passed and what you could not verify.
4. For interface changes, include relevant screenshots and consider keyboard use, accessibility and small screens.
5. Explain any migration, configuration or compatibility impact in the pull request.

Use synthetic or redacted examples. Never commit credentials, personal information, customer evidence or production exports. If AI tools helped produce a contribution, you remain responsible for its correctness, rights and validation.

## Security issues

Follow [SECURITY.md](SECURITY.md) rather than opening a public issue.
