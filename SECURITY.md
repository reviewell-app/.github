# Security reporting

Please do not disclose vulnerabilities, credentials or customer information in public issues or pull requests.

## Report privately

Use the affected repository's **Security → Advisories → Report a vulnerability** option when available. For organisation-wide concerns, [report privately through this repository](https://github.com/reviewell-app/.github/security/advisories/new).

If the private reporting option is unavailable, follow the affected product's published private contact route. A public issue may request a private contact channel, but must not include vulnerability details.

Include the affected product or repository, version or commit, a concise description, safe reproduction steps and the potential impact. Use test accounts and synthetic data; redact secrets and personal information.

## Scope and handling

Repository-specific security policies and supported-version information take precedence. This shared policy does not promise support for every historical release, a response deadline or a bug bounty.

Please allow time for investigation and coordinate disclosure with the maintainer. Do not access other users' data, disrupt services or continue testing beyond what is necessary to demonstrate the issue safely.
