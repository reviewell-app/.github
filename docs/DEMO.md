# Reviewell — public preview tour

[Organisation home](https://github.com/reviewell-app) · [Open preview](https://reviewell-removal-preview.vercel.app)

Explore three actual public views of the current Reviewell website. This is a website and process preview; the client workspace redirects to sign-in. No account is needed for this tour.

## Example context

An entirely fictional business, **Example Harbour Café**, has found a review it wants to understand before deciding what to do. The review URL and underlying facts have not been established.

The tour stops before sending a case. It demonstrates the public interaction and information architecture, not a completed removal or a working customer dossier.

## 1. Identify the issue

[Open the intake view →](https://reviewell-removal-preview.vercel.app/#check)

You will see content categories including Google reviews, profiles or websites, photos/video/AI and personal data. Select a category to see how the intake adapts. The public form allows a starting point without a URL.

For the fictional café, select **Google review**, leave the optional URL blank and use **Continue** to inspect the context step. If you type an example, use fictional details. Do not press the final send button during the tour.

**What to notice:** the workflow starts with classification and context; no platform action takes place merely because a category was selected.

## 2. Understand what evidence means

[Open the evidence guide →](https://reviewell-removal-preview.vercel.app/evidence-guide)

Explore the guidance on gathering relevant information. For the café example, distinguish what is known from what the business believes. Missing context is an open question, not proof of a policy breach.

**What to notice:** a useful case record needs the original content, context and relevant supporting material. The public GitHub repository is not an evidence upload channel.

## 3. Follow the proposed process

[Open the process view →](https://reviewell-removal-preview.vercel.app/how-it-works)

Read how a case moves from description and assessment to preparation and follow-up. Compare that process with the [product brief](PRODUCT.md).

**What to notice:** an assessment, a proposed action and an outcome are different stages. A person should understand which stage their case has reached and what the next step is.

## Where the public tour ends

[The client workspace](https://reviewell-removal-preview.vercel.app/dashboard) currently requires sign-in. The tour does not grant access to customer accounts, demonstrate a private customer's case or verify production readiness of account, payment or platform integrations.

For service availability and real enquiries, use [Reviewell's official website](https://reviewell.com). For technical collaboration, start with the [contribution guide](../CONTRIBUTING.md).
